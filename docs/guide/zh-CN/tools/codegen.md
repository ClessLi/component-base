# tools/codegen：错误码代码与文档生成器

## 工具定位与适用场景

`tools/codegen` 是一个独立命令行工具（`package main`），扫描 Go 源码中指定类型的**整型常量**
及其注释，生成三类产物：

1. **注册代码**（`*_generated.go`）：`Namespace` 常量 + `init()` 中对
   [errors](../libs/errors.md) 包的 `errors.Register(errors.DefaultCoder(...))` 调用；
2. **包装函数**（默认 `errors_generated.go`，需 `-wrapper`）：镜像 errors 包 API、
   自动注入本包 `Namespace` 的便捷函数；
3. **错误码 Markdown 文档**（需 `-doc-output`）：含错误码表格的中文文档。

适用场景：项目采用「整型常量 + 注释」定义错误码（如
[examples/code/0base.go](../../../../examples/code/0base.go)），希望注册逻辑、便捷 API 与
对外错误码文档全部由 `go generate` 自动维护，避免手工同步。

实现基于 `golang.org/x/tools/go/packages`（AST + go/types 类型检查），常量的实际值
（含 `iota` 表达式）由类型检查器求值，不靠文本推算。

## 安装与运行

```bash
# 仓库内安装
go install ./tools/codegen

# 或按已发布版本安装（需模块存在对应 tag）
go install github.com/ClessLi/component-base/tools/codegen@<version>
```

用法（`-type` 与 `-fullname` 必填，缺一即打印 Usage 并以退出码 2 结束）：

```text
codegen [flags] -type T -fullname projectFullName [directory]
codegen [flags] -type T -fullname projectFullName files...   # 必须同属一个包
```

不传位置参数时默认处理**当前目录**整个包。

## 命令行参数全表

依据 [codegen.go](../../../../tools/codegen/codegen.go) L41-52 与 main 流程：

| 参数                | 类型     | 默认值                         | 说明                                         |
|-------------------|--------|-----------------------------|--------------------------------------------|
| `-type`           | string | `""`（必填）                    | 常量类型名，逗号分隔列表；当前实现仅解析**第一个**类型的常量（见注意事项 1）  |
| `-fullname`       | string | `""`（必填）                    | 项目全名，用于文档标题                                |
| `-simplename`     | string | 同 `-fullname`               | 项目简称，用于文档正文与 namespace 默认值                 |
| `-namespace`      | string | `-simplename` 转小写           | 注册到 errors 包的错误码命名空间，生成为 `const Namespace` |
| `-output`         | string | 见下方规则                       | 注册代码输出文件名                                  |
| `-wrapper`        | bool   | `false`                     | 是否生成包装函数文件                                 |
| `-wrapper-output` | string | `<源目录>/errors_generated.go` | 包装函数输出路径；相对路径基于**源目录**拼接                   |
| `-doc-output`     | string | `""`（不生成）                   | 错误码 Markdown 文档输出路径；同时启用 Reference 链接自动生成  |
| `-trimprefix`     | string | `""`                        | 常量名前缀裁剪；当前生成产物均使用原始常量名，此参数未实际作用于输出（待确认）    |
| `-tags`           | string | `""`                        | 逗号分隔构建标签，**仅目录模式可用**，指定文件列表时传入会直接报错退出      |

`-output` 缺省命名规则（L124-135）：

- 无位置参数（默认当前目录）：`<目录基名，"-" 换 "_">_generated.go`，整体转小写；
- 恰有一个位置参数：按该参数去掉 `.go` 后缀的基名（`-` 换 `_`）计算，整体转小写
  （显式传目录名会走此分支，可能产生非预期文件名，建议显式指定 `-output`）。

执行顺序：解析包 → 解析常量 → （若 `-doc-output`）先生成文档并计算各错误码的文档行号
→ 生成注册代码 → （若 `-wrapper`）生成包装函数。所有 `.go` 产物经 `go/format` 格式化，
文件权限 `0600`，头部带 `Code generated by ...; DO NOT EDIT.` 标记。

## 错误码注释规范

### 基本格式

每个常量上方（Doc 注释）或行尾（单行 Comment）写：

```go
// ErrXxx - <HTTP状态码>: <描述，首字母大写，句号结尾>.
```

解析正则（`ParseComment`，L764-778）：

```text
\w\s*-\s*(\d{3})\s*:\s*([A-Z].*)\s*\.\n*
```

- HTTP 状态码必须为 **3 位数字**；
- 描述必须以**大写字母**开头；捕获组不含末尾句号（生成产物中描述无句号）；
- 注释不匹配时打印警告 `constant 'ErrXxx' have wrong comment format, register with 500 as default`，
  并按 `500` / `"Internal server error"` 注册与入表，**不会中断生成**。

### 可选 Reference 注释

```go
// ErrUnknown - 500: Contact system administrator with error details for investigation.
// Reference Message: Internal server error occurred, check logs for details
// Reference: https://example.com/docs/errors/unknown.md
```

解析正则（`ParseReference`，L784-809，均大小写不敏感）：

| 注释                                | 正则                                                  | 用途                          |
|-----------------------------------|-----------------------------------------------------|-----------------------------|
| `Reference Message:` / `Ref Msg:` | `(?i)(?:Reference\s+Message\|Ref\s+Msg)\s*:\s*(.+)` | 仅影响文档 Reference 列展示，不进入注册代码 |
| `Reference:` / `Ref:`             | `(?i)(?:Reference\|Ref)\s*:\s*(https?://\S+)`       | 作为 Coder 的 Reference URL 注册 |

注册用 Reference URL 的取值优先级：

1. 注释显式给出的 `Reference:` URL；
2. 未给出且指定了 `-doc-output` 时，**自动生成**指向错误码文档对应行的链接：
   `<git remote>/blob/main/<文档相对仓库根路径>#L<文档行号>`；
3. 否则为空字符串。

自动生成细节（`generateReferenceURL`，L812-895）：

- remote 取自 `git remote get-url origin`，SSH 形态（`git@host:path`）自动转 HTTPS，
  去掉 `.git` 后缀；仓库根取自 `git rev-parse --show-toplevel`；
- 分支固定为 `main`；行号优先用文档行号（`docLine`），未生成文档时回退源码行号；
- git 命令失败（非 git 仓库、无 origin 等）时 Reference 为空，不报错。

### 常量收集规则（`genDecl`，L899-1001）

- 只处理 `const` 声明中类型名与 `-type` 匹配的常量；`_` 跳过；
- 常量必须是整型（含 `iota` 表达式），非整型直接 `log.Fatal`；
- 注释优先取常量上方 Doc 注释，其次取行尾**单行** Comment；
- 包内找不到任何匹配常量时 `log.Fatalf("no values defined for type %s")`。

### 错误码编号建议

示例采用 `SSSMMM` 六位结构（SSS=服务 ID 3 位、MMM=模块内编号 3 位），如
`100001` 起为公共基础错误、`100101` 起为数据库错误。此为示例约定，工具本身不校验编号。

## 三类生成产物

以 [examples/code](../../../../examples/code/0base.go) 的 go:generate 指令为例：

```go
//go:generate codegen -type=int -fullname=CodeExample -namespace=codeexample -doc-output=../../docs/guide/zh-CN/examples/error_code_generated.md -wrapper
```

在 `examples/code` 目录执行 `go generate` 后得到：

### 1. 注册代码 code_generated.go

见 [code_generated.go](../../../../examples/code/code_generated.go)：

```go
// Namespace is the error code namespace for this package.
const Namespace = "codeexample"

func init() {
	errors.Register(errors.DefaultCoder(ErrSuccess, 200, "OK", "https://github.com/ClessLi/component-base/blob/main/docs/guide/zh-CN/errors/success.md", Namespace))
	errors.Register(errors.DefaultCoder(ErrValidation, 400, "Check input parameters and ensure they meet validation requirements", "https://github.com/ClessLi/component-base/blob/main/docs/guide/zh-CN/examples/error_code_generated.md#L20", Namespace))
	// ...每个常量一行
}
```

`errors.DefaultCoder(code, httpStatus, description, reference, namespace)` 的参数顺序与
[errors 包文档](../libs/errors.md)一致；包被 import 时 `init()` 自动完成注册。

### 2. 包装函数 errors_generated.go

见 [errors_generated.go](../../../../examples/code/errors_generated.go)。共 19 个函数，
签名与 errors 包同名函数一致（带命名空间参数的自动注入 `Namespace`）：

| 分类                      | 函数                                                                                                                                    |
|-------------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| 带码创建/包装（自动注入 Namespace） | `WithCode(code int, format string, args ...interface{}) error`、`WrapC(err error, code int, format string, args ...interface{}) error` |
| 带码判断（自动注入 Namespace）    | `IsCode(err error, code int) bool`                                                                                                    |
| 直通包装                    | `Wrap`、`Wrapf`、`New`、`Errorf`、`WithStack`、`WithMessage`、`WithMessagef`、`Cause`                                                        |
| 聚合                      | `NewAggregate`、`FilterOut`、`Flatten`、`Reduce`、`AggregateGoroutines`                                                                   |
| 标准库形态                   | `Is`、`As`、`Unwrap`                                                                                                                    |

### 3. 错误码文档

见生成产物 [error_code_generated.md](../examples/error_code_generated.md)（**不手工编辑**）。
结构：`# 错误码` 标题 → 功能说明（`code`/`message` 返回示例）→ 错误码表格：

```text
| Identifier | Code | HTTP Code | Description | Reference |
```

Reference 列展示规则（`generateDocs`，L705-719）：

| 注释提供                | 展示内容                        |
|---------------------|-----------------------------|
| 仅 Reference URL     | URL                         |
| 仅 Reference Message | 消息文本                        |
| 两者都有                | `<消息> (see details: <URL>)` |
| 都没有                 | 空                           |

注意：Reference 列展示与注册用 URL 是两套逻辑——只有 Message 时表格显示消息，
但注册代码里的 Reference 仍是自动生成的文档链接（若启用）。

## 最小可运行示例

```go
// Package myerr 定义 myservice 的错误码。
package myerr

//go:generate codegen -type=int -fullname=MyService -doc-output=./errors.md -wrapper

const (
	// ErrNotFound - 404: Resource not found, check the identifier.
	ErrNotFound int = iota + 100001

	// ErrInternal - 500: Contact system administrator with error details.
	ErrInternal
)
```

```bash
cd myerr && go generate
```

业务侧使用（依赖生成的 `Namespace`、`init()` 注册与 wrapper）：

```go
import "myproject/myerr"

err := myerr.WithCode(myerr.ErrNotFound, "user %s not found", id)
if myerr.IsCode(err, myerr.ErrNotFound) {
	// 404 分支
}
```

## 与其他库的协作关系

- **[errors](../libs/errors.md)**：生成代码 import errors 包并在 `init()` 注册
  `DefaultCoder`；wrapper 是 errors API 的命名空间预绑定形态。注册约束
  （code 非 0、namespace 非空、同 namespace 内 code 不重复）由 errors 包在运行时强制，
  违反会 panic，工具不做静态查重。
- **[core](../libs/core.md) / generic_server**：HTTP 响应侧按 Coder 的 `HTTPStatus()`
  写状态码、`String()` 写对外文案，错误码文档即对外契约。

## 注意事项、限制与常见问题

1. **`-type` 多类型限制**：虽然接受逗号分隔列表，但 `parseValues` 只解析第一个类型；
   多类型会为每个类型名重复生成同一份注册 `init()`，导致运行时重复注册 panic。
   请每次只传一个类型。
2. **`-trimprefix` 未生效**：裁剪后的名字仅存于内部字段，注册代码与文档均使用原始
   常量名（待确认是否为预留能力）。
3. **文档行号锚点会漂移**：自动生成 Reference 的 `#L<行号>` 按模板原始行数计算
   （首个错误码 = 模板行数 + 1）；若对生成的 Markdown 再做格式化排版
   （如仓库内 `error_code_generated.md` 已被重排），锚点行号与实际行号不一致。
   建议生成后保持原样，或显式为每个错误码写 `Reference:` URL。
4. **分支固定 main**：自动 Reference 链接固定 `blob/main`，非 main 主干仓库需显式
   `Reference:` 覆盖。
5. **注释格式失败不报错**：格式不符只降级为 500/"Internal server error" 并打印警告，
   CI 中建议检查生成日志或核对生成文档中的 HTTP Code 列。
6. **`-tags` 仅目录模式**：显式列出文件时传 `-tags` 直接 Fatal。
7. **生成产物勿手改**：三类产物均带 DO NOT EDIT 标记；修改错误码应改常量注释后重新
   `go generate`。
8. **单包约束**：文件列表模式要求所有文件同属一个包；解析到多个包会 Fatal。
